# Midtown Comics CLI

Headless HTTP CLI for reading Midtown Comics account data on a Linux server. It does not launch a graphical browser.

## Command groups

```text
midtown
├── auth       configure | login | browser-login | logout | status
├── account    show
├── orders     list | show | stats | export
├── wishlist   list | add | remove | export | prices | price-drops
├── preorders  list | total
├── product    show
├── search
├── collection stats | duplicates
└── doctor
```

The original shortcuts remain available:

```bash
midtown --json orders
midtown --json wishlist
```

Examples:

```bash
midtown auth configure
midtown auth login
midtown --json orders list
midtown orders stats
midtown orders stats --by month
midtown search "absolute batman" --include-preorders --show-out-of-stock
midtown preorders list
midtown preorders total
midtown orders show 4349113
midtown orders export --format csv --output orders.csv
midtown wishlist export --format json --output wishlist.json
midtown --json collection stats
midtown --json doctor
midtown auth logout
```

Login is automatic. Midtown's login form requires an invisible reCAPTCHA v3 token generated by page JavaScript, so a plain HTTP form post cannot authenticate. Instead, `midtown auth login` drives a headless Chromium (persistent profile, "Remember Me" checked) with the credentials stored by `midtown auth configure`, validates the session against the orders endpoint, and saves the cookies to `session.json`.

You normally never need to run it: when `orders` or `wishlist` gets the login page back (expired session), the client logs in automatically with the stored credentials and retries once. Requires `python -m pip install -e '.[browser]'` and `playwright install chromium`.

`midtown auth browser-login` runs the same automated login and, only if it fails (the reason is printed to stderr), starts a temporary HTTPS link through noVNC/ngrok so you can log in manually. Open it in a phone or computer, complete the normal Midtown Comics login, and the browser, display, VNC server, and tunnel are terminated automatically immediately after authentication.

The automatic mode can be disabled with `midtown auth browser-login --remote`.

The browser profile is retained at `~/.config/midtown-comics/browser-profile`; the temporary display, VNC server, and tunnel are closed after successful authentication or timeout. CAPTCHA/MFA are not required by the current Midtown flow, but the interactive browser remains compatible if the site introduces them later.

`preorders list` shows items that are not released yet: items with status `Pending` inside regular orders (release date read from each product page) plus items from Midtown's Previews pre-order program (`My Pre-Order Items`). `preorders total` sums their quantity and price.

`search` mirrors the site's filters: `--include-preorders` ("Include Pre-orders") and `--show-out-of-stock` ("Show out of stock") are off by default, as on the website. Each result includes `availability` (`in stock`, `pre-order`, `out of stock`) and `release_date`; cards the site lazy-loads are completed through `/search-load-product-body`.

`orders stats` calculates the number of orders, total comic units from order items, and total amount spent, broken down by order status; `--by month` groups spending per month. `collection stats` and `collection duplicates` use the order data already exposed by the authenticated account.

Catalog and write operations (`product show`, `wishlist add`, `wishlist remove`, and `wishlist price-drops`) are registered in the command tree but intentionally report that they are not implemented until their Midtown endpoints are verified. The CLI does not guess or bypass site protections.

The CLI automatically loads cookies from `cookies.json` and any refreshed session from `session.json`. After a successful browser login, the complete Playwright cookie objects for `www.midtowncomics.com` are captured in `session.json`, preserving attributes such as domain, path, `secure`, `httpOnly`, and expiry. After a successful authenticated orders or wishlist request, the current HTTP cookie jar is also persisted there, so normal cookie rotation does not require importing cookies again. This does not bypass server-side session expiration or CAPTCHA; if Midtown invalidates the session, `midtown auth browser-login` must be run again.

## Local configuration

Put your credentials in `.env` at the project root (already git-ignored, keep it mode `600`):

```text
MIDTOWN_EMAIL=you@example.com
MIDTOWN_PASSWORD=your-password
```

Lookup order: `MIDTOWN_EMAIL`/`MIDTOWN_PASSWORD` environment variables, then `.env` (override its path with `MIDTOWN_ENV_FILE`), then `~/.config/midtown-comics/credentials` written by `midtown auth configure`.

```text
~/.config/midtown-comics/credentials
~/.config/midtown-comics/cookies.json
~/.config/midtown-comics/session.json
```

If `cookies.json` exists, the CLI automatically loads only entries whose domain contains `midtowncomics.com`; cookies from other domains are ignored. Browser-exported JSON may be either a list of cookies or an object with a `cookies` list. Use mode `600` for all three files. Do not commit any of them.

## Development

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[test]'
pytest
midtown --help
```

## Important limitation

Midtown may require CAPTCHA or change its private HTML endpoints. The CLI reports a login failure rather than attempting to bypass CAPTCHA. Parsers are covered by fixture tests and should be updated when the site markup changes.
